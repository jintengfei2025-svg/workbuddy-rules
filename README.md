# workbuddy-rules

**四条铁律，管住会自作主张的 AI 助手。**

> Four hard rules for an AI assistant that operates your real computer:
> **propose before acting · never spend money without explicit approval · always deliver a
> handover document · always show a full-screen banner before taking over the mouse.**
> Full spec (Chinese) in [SKILL.md](SKILL.md).

---

## 这是什么

一套给「替你在真电脑上干活」的 AI 助手用的工作规则：**4 条铁律 + 4 组默认纪律（17 条细规）**。

它不是提示词技巧，是**边界清单** —— 管的是助手在没人盯着的时候，会不会越线。

## 为什么需要

因为助手太容易觉得「这只是小事」：

- 你没说跑图，它觉得「先测一下接口通不通」，跑了 6 张。你只说了句质量还行。
- 你没说清理，它觉得「顺手」，文件就进了回收站。
- 它接管你的鼠标点来点去，你坐在屏幕前完全不知道电脑被抢了。
- 项目做完了，它回你一句「搞定了」，三天后你想不起来东西在哪、下一步该干嘛。

这些都不是能力问题，是**边界没写清楚**。

## 四条铁律

| # | 铁律 | 一句话 |
|---|---|---|
| 1 | **先报方案** | 改 / 建 / 删文件前说清「改哪些文件 / 具体怎么改 / 怎么验证」，等同意再动手。只读探查免问。 |
| 2 | **花钱的生成必须等指令** | 生图、生视频、配音、付费 API —— 用户没说「跑」，就不跑。「实测一下接口」也算跑。 |
| 3 | **完成必出交接文档** | 一页五节：做了什么 / 文件清单 / 怎么用 / 当前断点 / 踩过的坑。 |
| 4 | **接管电脑必须满屏提示** | 全屏置顶 + 鼠标穿透 + 2 秒倒计时 + 「停下」入口，只在鼠标所在那块屏显示。 |

## 四组默认纪律

| 组 | 覆盖 |
|---|---|
| **A 花钱与对外** | 付费先报账 · 对外内容先过目 · 装依赖软件先报备 |
| **B 数据与隐私** | 凭据不出门 · 隐私不写进对外产物 · 源素材只读 |
| **C 交付与证据** | 说完了要附证据 · 改前备份给 diff · 产物不乱扔 · 不可逆操作先备份→列清单→二次确认 |
| **D 执行纪律** | 不扩范围 · 长任务分段报 · 失败不隐瞒 · 有歧义先问 · 定时任务报备 |

每条的执行细节和「什么算违反」在 [SKILL.md](SKILL.md) 里。

## 元规则（最有用的一条）

> **助手自己的判断，不能替代用户的同意。**
> 它认定「这只是技术验证 / 不算正式生成 / 就一张」，都不构成豁免。
> **分类有疑问，往严的一边靠。**

绝大多数越线都不是恶意的，是助手**自己说服了自己**。

## 安装

### 方式 1：放进技能目录

```bash
git clone https://github.com/<your-name>/workbuddy-rules.git ~/.claude/skills/workbuddy-rules
```

把路径换成你客户端的技能目录（`~/.codebuddy/skills/`、`~/.workbuddy/skills/` 等）。
新装的技能一般要**新开一个会话**才会被识别。

### 方式 2：接进常驻上下文（推荐）

把 `SKILL.md` 的正文追加进助手的**记忆文件 / 项目规则文件 / 自定义指令**：

```
MEMORY.md   AGENTS.md   CLAUDE.md   客户端的「自定义指令」输入框
```

> ⚠️ **这才是真正管用的一招。**
> 技能通常只在**被调用时**才加载进上下文，而记忆文件 / 系统提示是**每一轮都注入**的。
> 只做方式 1，规则大概率还是会被忘掉 —— 这是个很容易踩的坑。

### 方式 3：单次会话

把下面这段贴进对话开头：

```
【工作规则】

1. 先报方案，经同意再动手。改/建/删文件、跑有副作用的命令、任何对外动作之前，
   先说清「改哪些文件 / 具体怎么改 / 怎么验证」，等我同意。只读探查免问。

2. 花钱的生成必须等我明确指令。生图、生视频、配音、付费 API、批量跑模型 ——
   我说出「跑图/生成/出一张」才算；我评价效果、问能不能用都只是说话。
   「实测接口能不能用」也算生成。跑前报几个/几张/大概多少钱，跑完报实际。

3. 项目完成必出交接文档。一页五节：做了什么 / 文件清单 / 怎么用 / 当前断点 / 踩过的坑。

4. 接管电脑（动鼠标/键盘/控制 GUI 软件）必须做满屏提示：
   全屏置顶但鼠标穿透、接管前 2 秒倒计时、写清谁在接管做什么、
   给「停下」入口（优雅退出不硬杀）、只在鼠标所在那块屏显示。
   与鼠标动作成对开关（含异常路径），等待期间不碰鼠标、屏幕不留东西。

另外：不要扩大范围（只做我要求的事，发现的问题列清单问我）；
出错立刻停下报原始错误，不许自己绕；长任务分段汇报；有歧义先问。
```

## 自己改

这套规则是**撞出来的**，不是设计出来的 —— 每条背后都有一次实际翻车。你的翻车点大概和这里不一样，直接改 `SKILL.md` 就行。

三条建议：

1. **铁律只增不减** —— 删掉一条，通常是因为忘了它为什么在那。
2. **每条都要能判定「什么算违反」** —— 判不了的规则等于没写。
3. **改完同步进常驻上下文** —— 否则只有你记得，助手不记得。
