# 交接文档模板（精简版）

> **用法**：复制下面骨架填完，存成 `<项目名>-交接-<YYYY-MM-DD>.md`，放进项目目录，并且**直接打开给用户看**。
> **原则**：一页写完。读者是「三天后的用户」—— 他不记得任何上下文，只想知道三件事：这是什么、怎么用、下一步在哪。

---

# <项目名> 交接文档

**日期**：YYYY-MM-DD
**目录**：`<绝对路径>`

## 1. 做了什么

两到四句。说清这东西现在能干什么。**不写过程。**

## 2. 文件清单

| 文件 | 作用 |
|---|---|
| `绝对路径/文件` | 一句话 |

只列要动的和要用的。产物 / 脚本 / 配置分开写。

## 3. 怎么用

能直接复制的命令，或几步操作。命令给完整路径，别写「进目录后运行」。

```bash
# 例：
python -u path/to/script.py --args
```

## 4. 当前断点

- **已完成到哪**：
- **下一步该做什么**：（具体到文件 / 命令）
- **卡着的地方**：已知未解决的问题

## 5. 踩过的坑

| 现象 | 原因 | 怎么绕 |
|---|---|---|
| | | |

只写会让下一个人重复踩的。没有就写「无」。

---

## 反面例子（别这么写）

- 写成长串流水账「我先…然后…接着…」
- 只有结论，没有可复制的命令
- 不提断点和坑 → 下一个人重新踩一遍
- 篇幅超过一屏
- 只在对话里说「做完了」，不给文档

---

## 为什么这五节

| 节 | 回答的问题 | 缺了会怎样 |
|---|---|---|
| 做了什么 | 这东西是什么 | 拿到一堆文件不知道干嘛的 |
| 文件清单 | 该看哪个 | 在几十个文件里翻 |
| 怎么用 | 怎么跑起来 | 得回去问作者 |
| 当前断点 | 从哪继续 | 重新摸一遍现状 |
| 踩过的坑 | 哪些坑别踩 | **重复踩同一个坑** |

最后一节最容易被省，也是**最值钱的** —— 它省下的是别人的时间，不是自己的。
